Carve-Out Tutor — Technical Spec

The blueprint: two small Python programs on your laptop, one AI service, and a simple file-swap trick that keeps the store working while you rebuild it.

How it works, in plain language

The tutor app localhost:8000

What the learner uses: catalog, workspace, editor, Hint / Submit / Run, ownership %. Built with FastAPI. The pages are plain HTML and JavaScript.

The 3D asset store localhost:8001

The practice project: login, browse, cart, fake checkout, downloads, profile. The tutor starts it as a second server whenever you click Run project.

The trick: each carvable piece is its own file (store/pieces/auth.py, store/pieces/cart.py). The rest of the store only calls those functions. Carving shows the learner a stub with the same function names and empty bodies. Submit runs pytest on their file. When they pass, their file is the one that gets copied in the next time the store starts.

Components

Store App prd › The 3D Asset Store

FastAPI routes + Jinja2 templates in store/app.py. Routes: browse, login/logout, cart add/remove, cart, checkout (must be logged in and the cart must not be empty), download, profile. It calls pieces.auth and pieces.cart and never implements their logic itself. The database is data/store.db, so purchases survive restarts.

Carvable piece: Authentication (round 1) prd › Carving a Piece
hash_password(password: str) -> str
check_login(username: str, password: str, users: dict[str, str]) -> bool
is_logged_in(session: dict) -> bool

Called by: POST /login, POST /checkout, GET /profile. Breaks if wrong: anyone can check out, or the real user can't log in. Tests: tests/test_auth.py.

Carvable piece: Cart behavior (round 2) prd › Carving a Piece
add_item(cart: list[int], asset_id: int) -> list[int]       # no duplicates
remove_item(cart: list[int], asset_id: int) -> list[int]    # missing id = no-op
cart_total(cart: list[int], prices: dict[int, float]) -> float   # 2 decimals

Called by: the cart routes and checkout. Breaks if wrong: duplicates, items that won't remove, wrong totals. Tests: tests/test_cart.py.

Piece Definitions prd › Focused Task

tutor/pieces.py: hand-written stub, inputs/outputs, call sites, what breaks, and a model explanation for grading. Reference code is pulled live from the store files by function name, so it never goes stale.

Tutor Server prd › Hints · Tests and Swap-In · Running the Project
EndpointDoes
GET /api/stateRound, piece, task, editor code, results, %

PUT /api/codeAutosaves your draft

Test Runner and Store Launcher prd › Tests and Swap-In

tutor/runner.py. run_tests: puts your code in a temp folder, runs pytest with a 15 s limit, and reads per-test results from its XML report. run_store: copies the store, drops in passed pieces, restarts uvicorn on :8001, and waits until it answers.

AI Tutor (LLM) prd › Hints · Understanding Check
  • hint: never code. After a failure it gets the failing tests (passing ones marked done), so it targets what's broken. Code blocks in replies are stripped as a backstop.
  • grade: JSON score 0–10. Below 7 → a "you're missing X" hint, up to 2 times, then the full explanation.
  • answer: answers your questions about the piece.

Uses the openai library pointed at Groq. Switching to Gemini only changes environment variables.

Progress and Ownership prd › Saved Progress · Ownership Percentage

data/progress.json holds the current piece and each piece's status, draft, last results and check attempts. Ownership = your non-blank, non-comment lines ÷ all such lines in the store's .py files. It only goes up, and a passed piece never reverts.

Tutor Pages prd › Project Catalog · Screens and Layout

Catalog (1 card + "coming soon"), project page (Run / Start or Continue learning), and workspace: task, references and tutor chat on the left, with the editor and test results on the right (Programiz-style). The ownership bar is always in the top bar.

What could break

  • Groq is busy, down or the key is missing → "The tutor is busy, try again." Tests, swap-in, Run and the % keep working. Or switch to Gemini.
  • Your code hangs or crashes → the 15 s limit or the error shows as a failed test, with a hint. Nothing is swapped in.
  • The store won't start → an error message with the store's last log lines.
  • A hint leaks the answer → prompt rule + code-block stripping. We'll check it while building hints.

Simplified on purpose

  • Two hand-written pieces instead of the AI choosing what to carve.
  • Your code runs directly on your laptop instead of in a sandbox (fine for one learner, locally).
  • The store's tiny one-user login, fake checkout, on-page downloads and placeholder pictures.
  • One JSON progress file instead of a database. The store restarts on every Run instead of hot-swapping.
