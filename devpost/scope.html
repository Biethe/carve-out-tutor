Carve-Out Tutor (working title)

A browser-based AI tutor that hands you a working Python web project, cuts out one small piece, and coaches you, with hints but never the answer, until your own code replaces it and the page still works.

The unique kernel

You learn by rebuilding real pieces of a project that already works, and it keeps working the whole time.

The tutor gives you only the context you need. It coaches with hints, swaps in your code once the tests pass, and then checks that you understood it. Each round, a bigger share of the project is yours.

Mom does the meal. You peel the tomatoes and measure the flour, and you still get to taste the finished meal within the hour.

The core loop

Click a step or use the buttons to walk through one round.

Who it's for

Junior developers and beginners who know the basics of programming and want to build things. With coding agents, they could just prompt for a finished app and never learn how it works. Today they either let the AI do everything and learn nothing, or grind through tutorials that are cut off from anything they actually want to make.

What "working" looks like: the one-minute demo

  1. Opening (~5 s): a short intro to the project.
  2. The page: the working Python web page appears. It was prepared ahead of time.
  3. The carve-out: the tutor cuts out a piece and hands over a focused task.
  4. The learning: try, get stuck, get hints, try again, pass the tests, answer the comprehension question.
  5. The payoff: the page runs again, now with the learner's code inside it, written without the AI handing over the answer. The ownership score goes up.
  6. Round two: a different piece, and the score goes up again. That's the proof they're learning.

Boundary

Now: in the proof of concept
  • One project: a single small Python web page, prepared ahead of time.
  • One page in the browser: the task panel, a code editor, a way to run tests, and a preview of the running web page.
  • The carve loop: cut out a piece, show the focused context, give hints without answers, run tests, swap in the learner's code, run the page again, then ask the comprehension question and give graded feedback.
  • Rounds: two complete rounds, each on a different piece.
  • Ownership score: the percentage of the project's lines of code that the learner wrote, always visible and rising as they contribute.
  • Opening: a short intro in front of the prepared page. No live generation.
  • "Bring your own idea": shown as a feature of the product but not working in the PoC and not explored in the demo.
Later: worth doing, not now
  • Full interview: a full Devpost-style interview (scope, PRD, spec) before the AI builds anything.
  • Project catalog: about ten different kinds of web pages or websites to choose from.
  • Bring your own idea, for real: the AI generates a working project from the learner's idea, then carves it.
  • More project types: games, mobile apps (shown in a phone-sized preview), multi-page apps, and other languages.
  • In-browser terminal: for running arbitrary commands.
  • Many rounds: keep going until 40% of the project is yours, and eventually the whole core.
  • Users everywhere: accounts and saved progress across sessions.
Explicitly cut
  • Detecting or blocking outside AI tools: the learner shouldn't paste solutions from other AI tools, but the app can't reliably enforce that. The comprehension check is the PoC's answer.
  • Deployment for users worldwide: optional for the hackathon and not needed to prove the loop.

Identity & why it matters

Feel
Focused and never overwhelming. One small piece at a time, everything on one page. Inspired by learning to cook through small, real steps, and by the Devpost flipped-interaction skills.
For the learner
"How can I keep what AI offers us, quick implementations, while still learning?" They want to become an AI engineer who can implement things, understand how code fits into a real product, and learn about agents along the way.
